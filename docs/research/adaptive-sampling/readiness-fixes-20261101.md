# Виправлення після аудиту, 01.11.2026

Підтверджені програмні помилки аудиту виправлено. Текст і дві презентації
узгоджено з актуальним дослідженням. Підготовлено комплект для передавання
коду, моделей і результатів. Науковий метод не переналаштовувався: усі
191 контрольна сума замороженого набору збігаються.

Попередній [аудит](readiness-audit-20261101.md) залишено без змін як історичний
запис виявлених проблем. Цей звіт описує наступний стан, а не переписує аудит.

## Програмні зауваження

| Пункт аудиту | Виправлення та перевірка |
|---|---|
| 1. Небезпечна тестова база | Виправлено ключ `DefaultConnection`; тестовий DbContext явно замінюється. Перед видаленням звіряються сервер і приватне ім'я. Є негативні тести на інший сервер/каталог. Звичайний запуск 44 тестів проходить без підміни конфігурації процесу. |
| 2. Запізніла телеметрія | Історія зберігається, але поточні поля місця й пристрою змінюються лише за строго новішим часом. Контрприклад із пізнім «вільно» покрито тестом. |
| 3. Відсутні й старі дані | API розрізняє `current`, `missing`, `stale`, повертає окремий лічильник. Вільні/зайняті рахуються лише серед актуальних. Типовий строк 120 с, майбутні позначки теж непридатні. Покази карти, деталей та адміністративних списків перевірено через справжній SQL API й у браузері. |
| 4. Оновлення SAS | Перевірка строку виконується також при активному MQTT. З'єднання перестворюється з новим токеном. П'ять граничних перевірок виконуються під час компіляції; прошивка зібрана для ESP32. Тривалий апаратний прогін не проводився. |
| 5. Некоректні повідомлення | Перевіряються JSON-об'єкт, діапазон часу, довжина ідентифікатора та скінченна відстань 2-400 см. Постійні SQL-помилки форми запису ізольовано від повторного підключення потоку; інфраструктурні помилки не приховуються. Є 11 регресійних випадків парсера. |
| 6. Ініціалізація БД | Нова база створюється; правильний базовий ID міграції відновлюється тільки після звірення сумісної схеми. Несумісна схема відхиляється без стирання даних і позначення міграції як виконаної. Ізольовані SQL-тести охоплюють нову, мігровану, сумісну та неповну схеми. |
| 7. SignalR | Повторюється початкове підключення та підключення після остаточного розриву; таймер прибирається при закритті компонента. Додано опитування карти/деталей кожні 15 с і повідомлення про відновлення зв'язку. Два регресійні тести. |
| 8. Облікові дані | П'ять власних параметрів користувача збережено в локальному ігнорованому `device_secrets.h`. Приклад містить лише шаблони. Робочі `.env`, `appsettings.Development.json`, цей заголовок і скомпільовані бінарні файли виключено з комплекту. Ключі не публікувалися й не ротувалися. |
| 9. Ідентичність відправника | `deviceId` із JSON звіряється з `iothub-connection-device-id`. Розбіжність відхиляється; перевірено тестами. Інтеграційного запису в Azure під час виправлень не виконували. |
| 10. Залежності й перевірки | Невикористаний AutoMapper видалено. npm-залежності оновлено з узгодженим lock-файлом, `npm audit` показує нуль відомих вразливостей, включно з інструментами розробки. ESLint проходить без помилок і попереджень. Старі тести TodoItems/TodoLists прибрано; актуальні 44 тести лишилися. |

Додатково усунено підміну деталей при запізнілій відповіді попередньої парковки.
Завершення невдалого запиту не залишає індикатор очікування назавжди.
Ключі мови для нових статусів є українською й англійською. Розділення
клієнтських пакетів зменшило найбільший JS-файл приблизно до 337 кБ до gzip.
Мапа, UI й автентифікація мають окремі пакети.

## Текст і матеріали

- У Google Docs оновлено нативний зміст, включно з розділами 5-6. Усі 50
  посилань звірено з фактичними сторінками експортованого PDF.
- Уніфіковано шрифт змісту. Заповнено зміст завдання та назви восьми етапів
  календарного плану. План із підписами вміщується на сторінці 3.
- У розділах 2-3 описано лабораторний обсяг прототипу, поведінку за відсутності
  відстані, перевірку телеметрії, її актуальність, SAS і відновлення з'єднання.
  Надійність розпізнавання авто й тривалого хмарного прогону не приписується
  перевіркам програмного коду.
- Калібрування й фізичне встановлення описано як окрему умову застосування.
  Лабораторний показ потребує відбивача в робочому діапазоні для двох станів;
  монтаж під автомобілем у відкритому просторі не видається за перевірений.
- Висновок про виключення складових методу послаблено: нерівні бюджети не
  ізолюють причинний внесок кожної складової. Збережено негативний результат
  первинної вимоги нульових пропусків та всі компроміси остаточного протоколу.
- Джерело коду в бібліографії веде на конкретний репозиторій. Наявність
  неопублікованих файлів на GitHub не стверджується; передається окремий архів.
- Обидві Canva-презентації збережено з поточним методом, протоколом і графіками.
  Попередній напрям із напівмарковською моделлю прибрано. Візуальний стиль
  презентацій збережено. Додано два актуальні тексти виступу в цій папці.

Експорт має 58 сторінок. Офіційні дати й строки залишено автору за його прямим
дорученням. У PDF лишаються попередні реквізити форми; їх не слід вважати
підтвердженими датами подання. Вимоги кафедри до анотацій і форми службових
сторінок не надано, тому відповідність цим невідомим вимогам не заявляється.

в джоулях чи строк батареї, гарантована перевага на кожному місці або світовий
пріоритет загальної ідеї. Власний внесок - конкретне поєднання локального
