# Masters.Api - Smart Parking Map

Monorepo for the master's project about IoT-based parking occupancy monitoring.

## Solution structure

- `src/Web` - ASP.NET Core API, SignalR hub and map-oriented read endpoints
- `src/Worker` - Azure IoT Hub Event Hub consumer + simulated parking activity generator
- `src/Infrastructure` - EF Core, SQL Server storage and demo topology seed
- `../frontend` - React + Vite + MUI + Leaflet client
- `../sketch_dec15a` - Arduino sketch for the physical sensor

## Demo model

The demo works in hybrid mode:

- one real physical device sends readings for `ps-uzh-lot1-spot001`
- the remaining spots are generated by the simulation service
- the default demo city is `Ужгород`
- if browser geolocation is unavailable, the frontend falls back to the demo city map view

## Prerequisites

- .NET SDK `9.0.100`
- SQL Server / LocalDB
- Node.js `20.19+` or `22.12+`

## Build

```powershell
cd .\backend
dotnet build Masters.Api.sln -tl
```

## Database setup

Apply migrations before the first run:

```powershell
cd .\backend
dotnet ef database update --project .\src\Infrastructure --startup-project .\src\Web
```

The migration adds:

- `ParkingLots`
- `ParkingSpots.SourceKind`
- `ParkingSpots.ParkingLotId`
- telemetry history per spot

## Run Web API

```powershell
cd .\backend\src\Web
dotnet run
```

Development URLs:

- `https://localhost:5001`
- `http://localhost:5000`

## Run Worker

```powershell
cd .\backend\src\Worker
dotnet run
```

Main config keys:

- `ConnectionStrings:Masters.ApiDb`
- `RealtimeEventHub:Enabled`
- `RealtimeEventHub:ConnectionString`
- `RealtimeEventHub:EventHubName`
- `RealtimeEventHub:ConsumerGroup`
- `Simulation:Enabled`
- `Simulation:UpdateIntervalSeconds`

If `RealtimeEventHub:Enabled=false`, the worker still generates simulated parking activity.

Expected real device payload:

```json
{
  "deviceId": "ps-uzh-lot1-spot001",
  "ts": 1735689600,
  "distanceCm": 37.4,
  "occupied": true
}
```

## Run Frontend

```powershell
cd .\frontend
npm install
npm run dev
```

Frontend URL:

- `http://localhost:5173`

Optional env var:

- `VITE_API_BASE_URL` default is `https://localhost:5001`

## Public API

- `GET /api/map/overview`
- `GET /api/lots/{lotId}`
- `GET /api/spots/{spotId}/history?fromUtc=&toUtc=&maxPoints=`
- `SignalR hub: /hubs/parking`
- SignalR event: `mapSnapshot`

## Demo runbook

1. Start SQL Server / LocalDB.
2. Run `dotnet ef database update`.
3. Start `src/Web`.
4. Start `src/Worker`.
5. Start `frontend`.
6. Open `http://localhost:5173`.
7. Allow geolocation if you want the map to try centering around your location.
8. Click a parking lot marker to inspect available places and recent changes.
9. Trigger the Arduino sensor or keep the simulator running to show live updates.

## Suggested defense scenario

1. Show the city map with multiple parking lots.
2. Explain that one place is connected to a physical sensor and the rest are simulated for realistic city coverage.
3. Open one lot and show free vs occupied places.
4. Trigger a new sensor reading or wait for the simulator cycle.
5. Show that the marker, detail panel and history update without a page reload.
