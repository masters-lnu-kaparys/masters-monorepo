# Доопрацювання розкладу C3

Версія і початково відомі результати: [phase3-refinement-plan.json](../../docs/research/adaptive-sampling/phase3-refinement-plan.json). Попередню фазу, її код та негативні результати не перезаписано.

Запуск із кореня репозиторію у вже підготовленому середовищі фази 3:

```powershell
python research/parking_sampling/diagnose_schedule.py
python research/parking_sampling/refine_policy.py
```

`refine_policy.py` до навчання зберігає контрольні суми коду й списки місць. Працює тільки з `train_development` і `validation_development`, не відкриває остаточний тест. Він навчає таблиці на 256 місцях січня-червня, вибирає конфігурації на початкових 128 місцях липня-вересня, фіксує вибір та виконує додаткову перевірку на інших 512 місцях. Фіксовані таблиці використовують тільки останній виміряний стан, місцевий час і спостережувану тривалість. Повторний запуск зі зміненим навчальним кодом або планом у тій самій теці відхиляється.

Додаткові контролі були оголошені до нової перевірки. Їхні параметри необхідно вибрати до читання її результатів:

```powershell
python research/parking_sampling/refinement_controls.py
```

У виконаному дослідженні цей крок запущено під час навчання C3, до його переходу до нових 512 місць. Після фіксації всіх конфігурацій:

```powershell
python research/parking_sampling/refinement_controls.py --check
python research/parking_sampling/verify_refinement.py
python research/parking_sampling/report_refinement.py
```

Контролі: попередній C2 з обмеженнями пауз і просте нарощування інтервалу за послідовністю однакових вимірів. У виборі збережено початкові критерії; невдала конфігурація замінюється регулярними 60 секундами з нульовим виграшем.

Результати та навчальні таблиці залишаються в `.codex-work/parking-research-refinement-20261018`. Числові масиви зберігають місце та всі початки розкладу для парного порівняння. Звіт, CSV, PNG/SVG, джерела та контрольні суми зберігаються у `docs/research/adaptive-sampling/phase3-refinement-*`.

Перевірки від 1 доби містять основні вікна від 7 діб, тому це перевірка чутливості, а не другий незалежний набір. Десять повторів одного епізоду не рахуються як десять різних фізичних подій. Новий метод не слід називати CPO або теоретично оптимальним. Скорочення числа перевірок не означає виміряну економію батареї.

За результатами розроблення для фази 4 вибрано варіант C3 без часу доби. Вибір зроблено після додаткової перевірки, це явно записано у [phase4-entry-lock.json](../../docs/research/adaptive-sampling/phase4-entry-lock.json); сама навчена таблиця не змінювалася. Просте нарощування пауз залишається обов'язковим порівнянням. Повний C3 відкинуто через пропуски.

`trained_schedule.py` читає [компактну конфігурацію](../../docs/research/adaptive-sampling/phase3-refined-policy.json) та повертає паузу за `Observation`. Її три рядки точно відтворюють зафіксовану навчену таблицю. Це функція для дослідження та подальшої інтеграції; API й прошивку в цій фазі не змінювали.
