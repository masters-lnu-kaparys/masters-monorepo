# Masters.Api - Smart Parking Map

Monorepo for the master's project about IoT-based parking occupancy monitoring.

## Solution structure

- `src/Web` - ASP.NET Core API, SignalR hub and map-oriented read endpoints
- `src/Worker` - Azure IoT Hub Event Hub consumer + simulated parking activity generator
- `src/Infrastructure` - EF Core, SQL Server storage and demo topology seed
- `../frontend` - React + Vite + MUI + Leaflet client
- `../sketch_dec15a` - Arduino sketch for the physical sensor

## Demo model

The demo works in hybrid mode:

- one real physical device sends readings for `ps-uzh-lot1-spot001`
- the remaining spots are generated by the simulation service
- the default demo city is `Львів`
- if browser geolocation is unavailable, the frontend falls back to the demo city map view

## Prerequisites

- .NET SDK `9.0.100`
- SQL Server / LocalDB
- Node.js `20.19+` or `22.12+`

## Auth0 local setup

Create in Auth0:

1. SPA application for `frontend`
2. API / Resource Server with audience `https://masters.api`
3. roles `Admin` and `User`

Recommended local callback/logout URLs:

- `http://localhost:5173`
- `http://localhost:5173/auth/callback`

Enable Auth0 RBAC and add a Post-Login Action that assigns the default `User` role to new accounts and copies roles into both ID token and access token.

Ready-to-paste template:

- `../docs/auth0/assign-default-user-role-post-login.js`

Minimal action body:

```js
exports.onExecutePostLogin = async (event, api) => {
  const namespace = "https://masters.api";
  const { ManagementClient } = require("auth0");

  let effectiveRoles = event.authorization?.roles ?? [];

  if (effectiveRoles.length === 0) {
    const management = new ManagementClient({
      domain: event.secrets.domain,
      clientId: event.secrets.clientId,
      clientSecret: event.secrets.clientSecret,
    });

    await management.users.assignRoles(
      { id: event.user.user_id },
      { roles: [event.secrets.defaultUserRoleId] },
    );

    effectiveRoles = [event.secrets.defaultUserRoleName || "User"];
  }

  api.idToken.setCustomClaim(`${namespace}/roles`, effectiveRoles);
  api.accessToken.setCustomClaim(`${namespace}/roles`, effectiveRoles);
};
```

Action secrets:

- `domain`
- `clientId`
- `clientSecret`
- `defaultUserRoleId`
- `defaultUserRoleName`

## Run Worker

```powershell
cd .\backend\src\Worker
dotnet run
```

Main config keys:

- `ConnectionStrings:Masters.ApiDb`
- `RealtimeEventHub:Enabled`
- `RealtimeEventHub:ConnectionString`
- `RealtimeEventHub:EventHubName`
- `RealtimeEventHub:ConsumerGroup`
- `Simulation:Enabled`
- `Simulation:UpdateIntervalSeconds`
- `DeviceBinding:MaxParkingLotDistanceKm`

If `RealtimeEventHub:Enabled=false`, the worker still generates simulated parking activity.
If `Simulation:Enabled=false`, the worker only listens to real telemetry.
If `DeviceBinding:MaxParkingLotDistanceKm=0`, automatic lot matching by device coordinates is effectively disabled.

Expected real device payload:

```json
{
  "deviceId": "ps-uzh-lot1-spot001",
  "ts": 1735689600,
  "distanceCm": 37.4,
  "occupied": true,
  "latitude": 49.8387,
  "longitude": 23.9944
}
```

`latitude` and `longitude` are optional, but if they are present the worker can automatically link a new real device to the nearest parking lot inside the configured `DeviceBinding:MaxParkingLotDistanceKm` radius.

## Device commands

The admin panel can send commands to real devices through Azure IoT Hub direct methods.

Supported commands:

- `ping`
- `measureNow`
- `setThresholds`
- `reboot`

To enable command delivery in the Web API, configure:

- `IoTHubDeviceCommands:Enabled=true`
- `IoTHubDeviceCommands:ConnectionString=<IoT Hub service connection string>`

The connection string must have permission to invoke direct methods on devices.

## Public API

- `GET /api/map/overview`
- `GET /api/lots/{lotId}`
- `GET /api/spots/{spotId}/history?fromUtc=&toUtc=&maxPoints=`
- `GET /api/admin/lots`
- `POST /api/admin/lots`
- `PUT /api/admin/lots/{lotId}`
- `DELETE /api/admin/lots/{lotId}`
- `POST /api/admin/lots/{lotId}/spots`
- `PUT /api/admin/spots/{spotId}`
- `DELETE /api/admin/spots/{spotId}`
- `POST /api/admin/spots/{spotId}/commands`
- `SignalR hub: /hubs/parking`
- SignalR event: `mapSnapshot`

Access rules:

- `User` and `Admin` can use monitoring endpoints and SignalR
- only `Admin` can use `/api/admin/*`

## Demo runbook

1. Start SQL Server / LocalDB.
2. Run `dotnet ef database update`.
3. Start `src/Web`.
4. Start `src/Worker`.
5. Start `frontend`.
6. Sign in through Auth0 with a user that has role `Admin` or `User`.
7. Allow geolocation if you want the map to try centering around your location.
8. Click a parking lot marker to inspect available places and recent changes.
9. Open `/admin` with an `Admin` user to manage parking lots and spots.
10. Trigger the Arduino sensor or keep the simulator running to show live updates.

## Suggested defense scenario

1. Show the city map with multiple parking lots.
2. Explain that one place is connected to a physical sensor and the rest are simulated for realistic city coverage.
3. Open one lot and show free vs occupied places.
4. Show the Auth0-protected admin panel and explain that only `Admin` can change topology.
5. Add or edit a parking lot and one parking spot from the admin UI.
6. Trigger a new sensor reading or wait for the simulator cycle.
7. Show that the marker, detail panel and history update without a page reload.
