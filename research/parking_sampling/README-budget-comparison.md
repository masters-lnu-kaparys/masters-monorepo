# Порівняння C3/C4 за лімітом вимірювань

Це діагностика фази3 на вже використаних даних розроблення, не новий незалежний тест.
Попередні програми та результати не змінюються. Потрібне вже підготовлене середовище дослідження.

```powershell
python research/parking_sampling/run_budget_comparison.py fit
python research/parking_sampling/run_budget_comparison.py check
python research/parking_sampling/budget_coverage_annex.py fit
python research/parking_sampling/budget_coverage_annex.py check
python research/parking_sampling/report_budget_comparison.py
python research/parking_sampling/verify_budget_comparison.py
```

Перед останньою командою живі README/gate повинні мати точні знімки попереднього стану
у `history/` нової робочої теки. Верифікатор зіставляє попередні заморожені маніфести
через явний ланцюг історичних знімків. Старі квитанції тестів не перезаписуються.

План: [phase3-budget-comparison-plan.json](../../docs/research/adaptive-sampling/phase3-budget-comparison-plan.json).
Результати: `.codex-work/parking-budget-comparison-20261025/`.

269 розкладів:169 постійних за станом,90 двоступеневих,8 адаптацій S2 і незмінені C3/C4.
13 періодичних є підмножиною169. У8 комірках відтворено спільні початкові фази:
навчання256, налаштування128, перевірка256 та512, основні/чутливі вікна.

`banks/*.npz` зберігають цілі17 лічильників кожного BayId з усіма його фазами та вікнами,
гістограми й назви розкладів. Десять фаз не трактуються як десять незалежних місць.
Сирі S2/щохвилинні результати відтворюють попередні заморожені результати.

Суміш вибирає цілий розклад на початку вікна без доступу до майбутнього.
Ваги, зафіксовані після навчання/налаштування, оцінюються окремо від оптимістичних
меж, підібраних за самими перевірочними результатами. Останні мають точно рівний
очікуваний бюджет; вони не є готовою політикою з підтвердженим перенесенням.
Дробові лічильники у суміші означають сподівання, а не дробові фізичні події.

Загальна LP, змішування контролів, використання історії та адаптивні паузи
не заявляються як нові алгоритмічні винаходи. Мета - перевірити, чи потрібно
ускладнення C3/C4. Остаточний тест, Google Docs, Canva, API і прошивка не змінюються.

Додаток покриття оголошено після основного результату. Він дає контролям ту саму
паузу72с і вимагає також M60 не гірше кандидата. Це57 додаткових конфігурацій,
разом326. `coverage-annex-v2/` відокремлений від первинних результатів. Перша
технічна версія зупинилася на недопустимій LP; у версії2 такий випадок явно
зберігається як результат, без зміни політик або послаблення обмежень.
