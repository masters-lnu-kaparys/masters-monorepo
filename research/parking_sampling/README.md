# Дослідження розкладу вимірювань зайнятості

Ці інструменти працюють з офіційною історією City of Melbourne за 2019 рік. Вони не підключаються до API застосунку або його бази даних і не оцінюють політики на остаточному тесті.

Постановка, правила відбору й бібліографія: [протокол](../../docs/research/adaptive-sampling/phase1-protocol.md), [джерела](../../docs/research/adaptive-sampling/sources.md).

## Відтворення

Команди запускаються з кореня репозиторію у середовищі Python 3.12. Потрібно достатньо місця для ZIP 0,72 ГБ, CSV 7,45 ГБ, проміжних таблиць та результатів.

```powershell
python -m pip install -r research/parking_sampling/requirements.txt
python research/parking_sampling/test_prepare_data.py
python research/parking_sampling/download_source.py --workdir .codex-work/parking-research-phase2-20261018
python research/parking_sampling/prepare_data.py --workdir .codex-work/parking-research-phase2-20261018
python research/parking_sampling/verify_prepared.py --workdir .codex-work/parking-research-phase2-20261018
python research/parking_sampling/plot_data.py --workdir .codex-work/parking-research-phase2-20261018
```

`download_source.py` зберігає офіційні метадані, завантажує архів перевіреними діапазонами байтів, обчислює SHA-256 і перевіряє ZIP CRC. Додатковий файл `__MACOSX/._...csv` є службовим метафайлом, а не другою таблицею спостережень. У розпакований CSV він не потрапляє.

`prepare_data.py` читає всі рядки CSV зі строгим синтаксисом і явними комою та подвійними лапками. Це важливо: поле тривалості іноді містить тисячний роздільник у лапках. Для побудови історії використовуються фактичні часові позначки. Кеш проміжного Parquet визнається готовим лише за наявності відповідної квитанції з хешем джерела та версією парсера; незавершений файл не використовується.

Точний прохід по межах інтервалів визначає однозначний стан, суперечності й прогалини. Сумісні перекриття та суміжні записи одного стану об'єднуються. Межі маскованих днів, прогалин і суперечностей розривають неперервність. Час зберігається як секунди **локального календаря без UTC-зсуву**, а не як підтверджений UTC.

`verify_prepared.py` перевіряє контрольні суми, покриття вікон, відсутність перекриттів і незлитих повторів, календарний поділ та відсутність уже переглянутих місць в остаточній вибірці. Перевірка структури даних не є запуском методу на тесті.

`plot_data.py` читає тільки `train_development.parquet` і тільки основні вікна від 7 діб. Він створює описові рисунки навчальних даних, а не порівняння алгоритмів. До остаточної вибірки він не звертається.

## Ролі файлів

| Файл | Дозволене використання |
|---|---|
| `train_development.parquet` | Розроблення та навчання. |
| `validation_development.parquet` | Налаштування й вибір конфігурацій. |
| `exploratory_late_development.parquet` | Додатковий пошуковий матеріал; його не називати остаточним тестом. |
| `quarantine_train_reserved.parquet` | Історія зарезервованих місць за січень-червень; навчання дозволене після фіксації навчального конвеєра. |
| `quarantine_validation_unused.parquet` | Липень-вересень зарезервованих місць; для налаштування не використовується. |
| `quarantine_final_test.parquet` | Остаточний жовтень-грудень. Не запускати політики до фіксації алгоритмів і налаштувань. |

Імена `quarantine_*` означають процедурне відокремлення. Вони не є механізмом шифрування або технічного обмеження доступу. Саме дотримання протоколу та журнал запусків визначають незалежність оцінювання.

`windows.parquet` містить ідентифікатори та часові межі вікон. `is_primary=true` позначає основні вікна від 7 діб; інші збережені вікна мають не менше 1 доби та потрібні для перевірки чутливості до відбору. Алгоритми основного експерименту повинні явно фільтрувати `is_primary`.

Стовпці інтервалів: `bay`, `window_id`, `window_start`, `window_end`, `is_primary`, `start_local_seconds`, `end_local_seconds`, `state`. Інтервали мають вигляд [start, end), стан 0 означає «вільно», 1 - «зайнято».

Великі сирі файли та проміжні дані залишаються в робочій теці й виключені з Git. Підсумковий звіт, джерела, контрольні суми та код зберігаються окремо. Зменшення числа перевірок ще не є виміряною економією енергії фізичного вузла.

## Фаза 3: методи й налаштування

```powershell
python research/parking_sampling/verify_methods.py
python research/parking_sampling/run_phase3.py
python research/parking_sampling/build_phase3_report.py
```

`run_phase3.py` працює з уже підготовленою фазою 2. Він спочатку зберігає контрольні суми навчального коду й точний список 128 місць для налаштування. Тільки після цього відкриває січень-червень зарезервованих місць. Змінений навчальний код або інше джерело даних відхиляються при повторному використанні цієї фіксації. Для нової дослідницької версії потрібні окрема тека та явно задокументована зміна протоколу; тихо перезаписувати стару не можна.

Навчання охоплює обидві дозволені частини за січень-червень. Налаштування - тільки вибрані місця липня-вересня з `validation_development`. `data_access.py` технічно відмовляє читати остаточний тест, пізню пошукову частину та зарезервований липень-вересень. Кеш враховує джерело, склад місць, початки розкладу, випадкові зерна, код симулятора та параметри політики.

`simulation.py` містить незалежний простий симулятор. Функція вибору бачить лише час, останній виміряний стан та початок спостережуваної послідовності. `kernels.py` прискорює повтори однакових рішень, але не змінює доступну контролеру інформацію; еквівалентність перевірена окремо. `training.py` використовує майбутнє лише як навчальні цілі всередині навчального вікна.

`markov_baseline.py` розв'язує лінійну програму S2 за додатком B. Перевірено числовий приклад статті; паркувальна реалізація називається адаптацією S2. `policies.py` задає регулярні інтервали, інтервали за станом, C1/C2 та вилучення складових. `fixtures/C0-archived-pilot.npz` є незміненою історичною таблицею з попереднього аудиту. Її дані й старий граничний випадок відрізняються, тому це не чистий контроль однієї зміни алгоритму.

Результати: `.codex-work/parking-research-phase3-20261018/`. `models` містить навчальні таблиці та переходи; `candidate-results` - масиви 17 лічильників за місцем і початком розкладу та гістограму затримок. `tuning-results.json` зберігає всі конфігурації, результати й вибір. `frozen-policies` та `frozen-policy-definitions.json` задають вибрані точки; модельні переходи S2 для нових місць у майбутньому оцінюватимуться тільки за незмінною навчальною історією. Числа епізодів у зведенні включають десять повторів, а не означають десять різних фізичних подій.

`build_phase3_report.py` створює звіт, CSV і PNG/SVG лише з налаштування. Для побудови джерельного реєстру потрібні збережені `sources/source-manifest.json`, `sources/collaborative2021.txt` з цієї фази; це архівування літератури, а не залежність симулятора. Посилання на первинні PDF/публікації та їхні SHA-256 є в [реєстрі джерел](../../docs/research/adaptive-sampling/phase3-sources-evidence.json).

Поточний результат: **C1/C2 не пройшли всі основні умови; покращення не заявляється**. За основним відбором застосовується регулярний інтервал 60 секунд. Ресурсні точки та негативний результат збережені. Другорядне зіставлення бюджетів уточнено після налаштування через облік першого виміру у вікні; первісний варіант збережено, [зміна позначена](../../docs/research/adaptive-sampling/phase3-resource-selection.json). Перш ніж відкривати остаточний тест, потрібне доопрацювання кандидата або погоджена інша мета експерименту. [Повний звіт](../../docs/research/adaptive-sampling/phase3-method-report.md).
