# Комплект магістерської, 01.11.2026

Починайте з цього файла після розпакування архіву. Шляхи нижче відносні до
кореня комплекту. Переносьте всю папку, включно з `.codex-work`: у ній збережено
моделі, лічильники та підготовлені відкриті дані. Назва цієї папки не означає,
що її вміст у комплекті можна видалити.

## Що передається

- `docs/delivery/thesis-20261101.pdf` - експорт актуальної роботи, 58 сторінок.
- `backend`, `frontend`, `sketch_dec15a` - код прототипу й демонстрації.
- `research/parking_sampling` - реалізації, перевірки та зафіксовані дослідницькі скрипти.
- `docs/research/adaptive-sampling` - протоколи, джерела, таблиці, рисунки, історія рішень.
- `.codex-work/parking-*` - готові моделі, підготовлені розділи даних, проміжні результати й негативні перевірки попередніх варіантів.
- `DELIVERY-MANIFEST.json` - розмір та SHA-256 кожного файла архіву, крім самого маніфесту.
- `readiness-fixes-20261101.md` - відповідь на кожну групу зауважень аудиту.

Збережені старі звіти описують стан на свою дату. Для поточного стану
використовуйте `CURRENT.md` і звіт про виправлення, а не історичний README фази 4.
Посилання на GitHub у роботі ідентифікує репозиторій; нові локальні файли в цьому
сеансі туди не завантажувалися. Версію передавання визначають архів і його хеш.

## Найкоротший показ програми

Потрібен Node.js 22.13 або новіший; перевірено на 22.23.2. У PowerShell:

```powershell
cd frontend
npm ci
npm test
npm run build
npm run preview
```

Відкрийте `/measurements` за адресою, яку надрукує Vite. Ця сторінка працює без
входу, SQL Server, Azure та ESP32. Вона відтворює записи, а не вимірює місце наживо.
Є три приклади, покроковий показ, пояснення пауз і збереження журналу CSV.
Статистика 867 місць подана окремо від короткого прикладу.

## Перевірка дослідницького результату

Потрібні Python 3.12 і пакети з точними версіями. Перевірено на Python 3.12.14.
Із кореня комплекту:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r research/parking_sampling/requirements.txt
.\.venv\Scripts\python.exe tools/verify_research_delivery.py
.\.venv\Scripts\python.exe -m unittest discover -s research/parking_sampling -p 'test_*.py'
```

Перша перевірка звіряє 191 незмінний файл та підсумовує лічильники 17 методів у
двох вибірках. Очікується `passed: true`, `frozen_files: 191`,
`policy_cohort_sums: 34`. Друга виконує 131 програмний тест. Це перевірка
збережених результатів і реалізацій, а не новий незалежний польовий експеримент.

Точні підготовлені Parquet-файли також включено. Повторний експорт демонстрації
можливий скриптом `research/parking_sampling/export_demo.py`; він читає зафіксовані
моделі й записи та перевіряє їхні хеші. Доцільно запускати його в окремій копії
комплекту: він записує клієнтські демонстраційні файли.

Скрипти навчання й остаточного оцінювання збережено для перевірки процедури.
Для читання готового результату запускати їх повторно не потрібно. Повний
новий прогін із сирого CSV в новому середовищі після архівування не заявляється.
Відтворення Parquet іншим паралельним записом може дати інші байти; охоронні
перевірки хешів навмисно цього не ігнорують.

## Походження даних

Джерело - City of Melbourne, *On-street Car Parking Sensor Data - 2019*.
Офіційний URL, ліцензійні метадані, SHA-256 архіву та CSV збережено в
`.codex-work/parking-research-phase2-20261018/source/source-manifest.json`.
Метадані джерела й підготовлені вибірки включено; сирі ZIP (~717 МБ), CSV
(~7,45 ГБ), завантажувальні частини й тимчасову DuckDB до комплекту не включено.
Потрібний архів завантажує `download_source.py`; правила очищення описані у
звітах фази 2. Початкові часові позначки інтерпретуються за зафіксованим протоколом.

## API, база і фізичний вузол

Для цієї частини потрібні .NET SDK 9.0.100, SQL Server / LocalDB та власна
конфігурація. Інструкції - у кореневому й `backend/README.md`. Перевірки:

```powershell
dotnet test backend/tests/Application.UnitTests/Application.UnitTests.csproj /p:UseArtifactsOutput=false
dotnet build backend/Masters.Api.sln -tl /p:UseArtifactsOutput=false
```

Вебтести створюють приватні бази з випадковими назвами й перевіряють сервер та
ім'я перед видаленням. Робоча база для цих тестів не потрібна. Перед міграцією
власної наявної бази потрібна її звичайна резервна копія. Нова база створюється
міграціями; сумісна схема без історії розпізнається, несумісна зупиняє запуск
з поясненням. Автоматичного руйнівного перетворення довільної старої схеми немає.

Параметр `TelemetryFreshness:MaxAgeSeconds` типово дорівнює 120 с. Після його
завершення старий вимір лишається в історії, а місце виключається з поточного
підрахунку вільних/зайнятих. Це інженерне правило актуальності, окреме від
дослідницького планувальника. Клієнт перевіряє карту також кожні 15 с.

`appsettings.Development.json`, робочі `.env` та `device_secrets.h` не включено.
Для налаштування використовуйте базові `appsettings.json`, приклади й власні
локальні значення. Нічого переносити з чужих ключів не потрібно. Як зібрати
прошивку, описано в `sketch_dec15a/README.md`. Компіляцію перевірено; прошивання,
тривалу роботу в Azure, точність на авто та споживання батареї цим комплектом
не підтверджено. Адаптивний планувальник виконується у дослідницькому коді й
браузері; керування ним фізичним вузлом є подальшою інтеграцією.
