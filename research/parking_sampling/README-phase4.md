# Остаточне оцінювання за зафіксованим протоколом 0.2

Для повторного оцінювання з опублікованими параметрами скористайтеся
[інструкцією відтворення](../../docs/delivery/README.md). Порядок нижче
описує початковий запуск і потребує проміжних матеріалів розроблення.

Виконувати з кореня репозиторію після завершення `close_phase3.py`. [Протокол](../../docs/research/adaptive-sampling/phase4-display-protocol.md) містить окрему постановку щодо якості карти, незмінний список 867 місць, пороги висновку та обов'язкові компроміси. Початковий нульовий M60 не виконано на розробленні; він залишається окремим негативним результатом.

```powershell
python research/parking_sampling/close_phase3.py
python research/parking_sampling/phase4_pipeline.py train
python research/parking_sampling/phase4_pipeline.py evaluate
python research/parking_sampling/phase4_pipeline.py analyze
```

`close_phase3.py` читає тільки вже відомі дослідницькі артефакти та метадані якісних вікон. Він перевіряє попередні хеші й тести, зберігає старий статус, створює новий протокол і каталог методів, фіксує повний код і версії залежностей. **Ця команда не читає остаточних станів та не оцінює жодного методу на тесті.**

`train` спочатку звіряє фіксацію. Потім дозволено читати лише січень-червень зарезервованих місць і додавати локальні статистики з незмінними спільними оцінками. Спільні оцінки, ваги політик, дії й усі зерна не змінюються. Нові таблиці хешуються до оцінювання. S2 використовує раніше зафіксовані переходи за січень-червень, ширша історія цього контрольного методу розкрита в каталозі.

`evaluate` записує маркер початку перед першим читанням остаточних станів. Всі зафіксовані складові обчислюються на тих самих вікнах і початкових фазах. За переривання можна продовжити лише з тими самими хешами: завершені масиви перевіряються й повторно не обчислюються. Зарезервований липень-вересень не відкривається. Не міняти код після перегляду результатів заради кращого показника.

`analyze` використовує зафіксовані ваги, основне зерно та всі десять додаткових розподілів таблиць. Звітує реалізовані й очікувані результати окремо, всі пропуски та особисті погіршення. Основний висновок стосується автора проти щохвилинного контролю на довгих вікнах; додаткові зіставлення не підміняють його. Тестові ваги контрольних методів не оптимізуються. Якщо результат негативний, він таким і залишається.
